# Multi-Tenant Architecture

Multi-tenant systems succeed or fail on how explicitly they enforce boundaries. The simplest approach is application-layer scoping, where every query and write path carries a tenant identifier and services reject cross-tenant access by default. This is straightforward to understand and can work well when the codebase is disciplined, but it depends on every access path remembering to apply the right filters. One missing condition in a reporting query or background job can turn into a real data leak.

Row-level security, or RLS, moves part of that enforcement into the database. Policies can ensure that even if the application issues a broad query, the database only returns rows allowed for the active tenant context. RLS is stronger as a safety net, but it also adds operational complexity. Teams need a clean way to set session context, test policy behavior, and reason about privileged maintenance tasks. For many systems, the practical answer is layered defense: application-level scoping for clarity, plus database-level controls for the highest-risk tables.

Joyus also benefits from governance tiers. A useful model is tier 1 for public or low-risk reference content, tier 2 for normal internal documentation, tier 3 for restricted client or operational material, and tier 4 for highly sensitive records that require exceptional handling or are excluded from AI retrieval entirely. Those tiers let the platform enforce different retention, auditing, and entitlement rules instead of pretending every document should be handled the same way.

Entitlement gating sits on top of the isolation model. Even inside one tenant, a user should only retrieve content that matches their product, account, or session context. That means source membership, product mappings, and access resolution cannot be an afterthought. Strong multi-tenant design is not only about keeping tenants apart; it is also about making sure the right user sees the right content within a tenant, with evidence that the decision was enforced.
